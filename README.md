# Linux troubleshooting labs

Цель мини-лаб:
- воспроизвести production-like инциденты;
- отработать алгоритм поиска и устранения инцидентов;


# Оглавление

1. [Обзор](##Обзор)
2. [Подготовка необходимого окружения](##Установка)


## Обзор

Данный проект представляет собой лабораторную среду для симуляции реальных инцидентов, возникающих в Linux-инфраструктуре.
Каждый сценарий описывает типичную проблему из production-среды, которую необходимо диагностировать и устранить, используя Linux-инструменты.


В качестве окружения будут созданы две виртуальные машины:
1. Ubuntu Server (cервер): эта машина будет имитировать сервер, к которому мы будем подключаться по `ssh`, искать проблемы и устранять их.
2. Ubuntu Desktop (Виртуальная машина с GNU, рабочая машина), с которой будем подключаться к серверу для исправления инцидентов.


В ходе проекта разберем 5 возможных инцидентов:

##### Инцидент №1: система работает медленно и не отвечает
##### Инцидент №2: веб-сервис недоступен или возвращает 502/504
##### Инцидент №3: домен не резолвится или сайт недоступен по имени
##### Инцидент №4: нестабильное соединение и высокая задержка
##### Инцидент №5: сервис работает, но недоступен извне



## Установка

Для работы понадобится две виртуальные машины:
- Сервер (Ubuntu server)
- Рабочая машина (Ubuntu Desktop)


Создать виртуальные машины можно используя VirtualBox от Oracle.
Ссылка на официальный сайт для скачивания: [VirtualBox](https://www.virtualbox.org/wiki/Downloads)


Эти виртуальные машины должны будут иметь два подключения:
1. NAT (доступ в Интернет. Обычно создается по умолчанию)
2. Internal network, который будет соединять две наши машины. Используйте имя `Net_lab`.



#### 1. Подготовка сервера

После скачивания и установки VirtualBox, необходимо скачать виртуальный диск (ISO) операционной системы Linux.
Рекомендую использовать ISO Ubuntu Server 24.04.4 TLS. Скачать можно по [ссылке](https://ubuntu.com/download/server/thank-you?version=24.04.4&architecture=amd64&lts=true)

Далее необходимо создать виртуальную машину (сервер) в VirtualBox со следующими системными требованиям:
- 2vCPUs
- 2GB RAM
- 20GB disk space
- 2GB дополнительный жесткий диск (добавим позже).

Запускаем виртуальную машину, устанавливаем операционную систему.


После установки выключаем виртуальную машину, после чего создаем в настройках виртуальной машины два адаптера в разделе "Networking":
1. Первый адаптер оставляем как есть (должен быть создан по умолчанию "NAT")
2. Добавляем второй адаптер: 
    - Attached to: `Internal network`
    - Name: `Net_lab`

3. После настроек виртуальных кабелей необходимо создать и добавить еще один жесткий диск на 2GB.

3. Сохраняем настройки и запускаем виртуальную машину снова. Это было необходимо, чтобы наш сервер и рабочая виртуальная машина с GNU в будущем были в одной подсети и смогли общаться друг с другом.



Логинимся на сервер и выполняем следующие действия:

1. Прописываем статический IP для интерфейса, который пока без IP-адреса (второй интерфейс, подключенный к "Internal Network"):
    1. Узнаем имя созданного интерфейса: `ip -c addr sh`. Второй в списке интерфейс без IP - это тот интерфейс, который нам нужен. Сохраняем/запоминаем его
    2. Создаем конфиг файл командой `sudo vim /etc/systemd/network/10-static.network` и добавляем туда:
        ``` bash
        [Match]
        Name=ens33

        [Network]
        Address=192.168.20.10/24

        [DHCP]
        No=yes
    ```
    3. Сохраняем конфиг файл и перезагружаемся командой `sudo reboot`
    4. После перезагрузки логинимся и проверяем, получил ли интерфейс IP: `ip -c addr sh`


2. Настраиваем `sshd` сервер:

    - `sudo apt update`
    - `sudo apt install -y openssh-server`
    - `sudo systemctl enable --now ssh`

    - Проверяем статус: `sudo systemctl status ssh` - должен быть "active (running)".


3. Устанавливаем и настраиваем firewall (ufw):
    1. `sudo apt install -y ufw`
    2. Разрешаем ssh трафик: `sudo ufw allow from 192.168.0.11/24 to any port 22`
    3. `sudo ufw enable`



#### 2. Виртуальная машина с GNU

В качестве этой машины может быть любая VM на ОС Linux. Для удобства лучше использовать desktop-версию Linux с GNU. Например, [Ubuntu desktop](https://ubuntu.com/download/desktop)

Минимальные рекомендуемые системные требования:
- 2vCPUs
- 4GB RAM
- 50GB disk space

После установки операционной системы выключаем виртуальную машину, после чего создаем в настройках виртуальной машины два адаптера в разделе "Networking":
1. Первый адаптер оставляем как есть (должен быть создан по умолчанию "NAT")
2. Добавляем второй адаптер: 
    - Attached to: `Internal network`
    - Name: `Net_lab`
3. Сохраняем настройки и запускаем виртуальную машину снова.


После запуска выполняем следующие действия:
1. Узнаем имя созданного интерфейса: `ip -c addr sh`. Второй в списке интерфейс без IP - это тот интерфейс, который нам нужен. Сохраняем/запоминаем его
2. Создаем конфиг файл `/etc/netplan/99-static.yaml` и добавляем туда следующий код (`имя_интерфейса` заменяем именем реального интерфейса):

``` bash
network:
  version: 2
  renderer: networkd
  ethernets:
    имя_интерфейса:
      addresses:
        - 192.168.20.11/24
```
3. Сохраняем изменения, изменяем доступ на `600` для `/etc/netplan/99-static.yaml` и применяем изменения командой `sudo netplan apply`
4. Проверяем, присвоился ли адрес интерфейсу командой `ip -c addr sh`
