# Linux troubleshooting labs



## Обзор

Данный проект представляет собой лабораторную среду для симуляции реальных инцидентов, возникающих в Linux-инфраструктуре.
Каждый сценарий описывает типичную проблему из production-среды, которую необходимо диагностировать и устранить, используя Linux-инструменты.


В ходе проекта разберу 6 возможных сценариев/инцидентов:

- Группа инцидентов №1: система работает медленно и не отвечает
- Группа инцидентов №2: веб-сервис недоступен или возвращает 502/504
- Группа инцидентов №3: домен не резолвится или сайт недоступен по имени
- Группа инцидентов №4: нестабильное соединение и высокая задержка
- Группа инцидентов №5: сервис работает, но недоступен извне
- Инцидент №6: пользователь не может залогиниться - после успешного ввода логина и пароля через секунду система снова просит логин и пароль (login loop)


Для каждой группы инцидентов создан скрипт, который создает проблему в системе, имитирующую реальный инцидент (перегружен диск / упал сервис и т.д.). Перед началом работы с каждым инцидентом, нужно будет запускать этот скрипт командой, которая будет указана в самом начале каждого сценария.


Каждая группа инцидентов содержит следующие разделы:

- тикеты (Monitoring -> Alert -> автоматически созданные ticket или созданный пользователем)
- отчеты об исправлении, которые содержат:
    - Описание ситуации
    - Источник инцидента
    - Сработавшие алерты (если были)
    - Влияние на сервис
    - Таймлайн инцидента
    - Описание диагностики (какие инструменты/команды использовались)
    - Первопричина
    - Решение по исправлению ситуации
    - Рекомендации по предотвращению в будущем
    - Итоговый статус
