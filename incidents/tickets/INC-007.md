# INC-007 504 Gateway Timeout (web-api)

## Severity: P1
## Status: Open
## Service: web-api / nginx
## Time: 2026-05-25 12:15 UTC+3
---

## Summary
Increased rate of 504 Gateway Timeout errors on `/` via nginx reverse proxy.

---

## Impact
- ~50% requests failing with 504
- User-facing timeouts and failed requests

---

## Detection
- Monitoring alert (high 504 rate)

---

## Error
- 504 Gateway Timeout
- upstream timed out (110: Connection timed out) while reading response header from upstream


---

## Current state
- nginx: running
- backend: running
- CPU / RAM: normal
- network: OK

---

## Suspected cause
Backend response latency exceeding nginx `proxy_read_timeout`.

---

## Actions taken
- Restarted backend
- Verified nginx config
- Collected logs (nginx + backend)

---

## Next steps
- Investigate slow endpoint / latency spike
- Review timeout settings
- Add latency monitoring for upstream
