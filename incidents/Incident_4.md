# Инцидент №4: login-loop (пользователь вводит логин и пароль правильно, но не может залогиниться, потому что система запрашивает логин и пароль снова и снова).


Цель: научиться диагностировать и устранять проблемы при ssh-логине (login loop), когда пользователь успешно проходит аутентификацию, но сессия сразу же завершается.
Инструменты: tail, journalctl, getent.


Как воспроизвести инцидент:
1. Выполнить следующие команды (в рамках скрипта будет предложено придумать имя нового пользователя и пароль, для которого будет воспроизведен инцидент):
- `chmod +x ~/linux-troubleshooting-labs/scripts/lab_4/incident_4.sh`
- `~/linux-troubleshooting-labs/scripts/lab_3/incident_4.sh`

2. После запуска скрипта добавьте исключение для созданного пользователя, чтобы для него была разрешена аутентификация по паролю в `/etc/ssh/sshd_config` на сервере, после чего нужно перезапустить `sshd` сервис.

Пример того, что нужно добавить в конец файла (подставьте имя созданного пользователя вместо `new_user`:

``` bash
Match User new_user
    PasswordAuthentication yes
```

3. Попробуйте сделать несколько попыток входа на сервер по ssh с рабочей машины от имени нового пользователя.

# [Не могу зайти на сервер по SSH](/incidents/tickets/INC-008.md)

Краткое описание инцидентa (симптомы): пользователь не может зайти на сервер по SSH. Сообщает, что вводит пароль правильно, но войти не получается.


Источник инцидента: тикет от пользователя



Таймлайн инцидента:
- 25.05.2026 14:00:00 - Проблема возникла
- 25.05.2026 15:10:00 - Создан тикет в системе
- 25.05.2026 15:23:00 - Начата диагностика
- 25.05.2026 15:31:00 - Найдена причина
- 25.05.2026 15:35:00 - Инцидент устранен



Диагностика:
1. `tail -f /var/log/auth.log` или `journalctl -u ssh`
2. `getent passwd username`
3. `cat /etc/shells`


Первопричина:
- Установлен shell, которого нет в списке доступных shell


В реальной работе возможны следующие причины, по которым может возникать ошибка 504:
- Закончилось место на диске: проверить `df -h`
- Доступы (у пользователя нет доступа к своему домашнему каталогу или файлам): проверить `ls -la ~username`
- Проблемы с config-файлом ssh (запрещен вход пользователю, ограничен доступ по IP, ошибки в `sshd_config`): проверить `/etc/ssh/sshd_config` и config-файлы в `/etc/ssh/sshd_config.d/`
- PAM: искать `pam_error` в `/var/log/auth.log`, проверить pam-конфиги `cat /etc/pam.d/sshd`
- Проверяем, заблокирован ли пользователь: `faillock --user username`


Решение:
- Восстановить shell: `sudo usermod -s /bin/bash username`
- Попросить пользователя попробовать войти на сервер по ssh снова


Итоговый статус: после того, как пользователь подтвердит, что удалось войти на сервер по shh - Инцидент решён (Resolved)
